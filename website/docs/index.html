Requirements

  • OS: macOS or Linux
  • Build: Rust 1.80+, Node.js 22.12+ (for source install)
  • Interactive: a terminal with Kitty graphics — Ghostty, kitty, or WezTerm
  • Headless: any terminal (including Apple Terminal)

Install

Fastest path — clones main and builds from source:

curl -fsSL https://raw.githubusercontent.com/zent7x/terminal-fenster/main/install.sh | bash

Manual checkout:

git clone https://github.com/zent7x/terminal-fenster.git
cd terminal-fenster
./install.sh

Installs to ~/.local/share/terminal-fenster and links ~/.local/bin/terminal-fenster. Uninstall:

./uninstall.sh                 # keep browser profile
./uninstall.sh --purge-profile   # remove profile data

Quick start

terminal-fenster setup              # verify engine + terminal
terminal-fenster doctor             # capability report
terminal-fenster open example.com   # interactive browsing
terminal-fenster open example.com --headless

From a checkout without installing:

tools/dev-terminal-fenster.sh open example.com

Keyboard shortcuts

  • ctrl+q — quit
  • ctrl+r — reload
  • ctrl+l — focus URL / search bar
  • ctrl+f — find in page
  • ctrl+= / ctrl+- / ctrl+0 — zoom
  • ctrl+left / ctrl+right — back / forward
  • Mouse — click, hover, drag, scroll forwarded to the page

Terminal support

TerminalGraphicsNotes
GhosttyKittyPrimary dev target, verified E2E
kitty, WezTermKittyExpected to work; not CI-tested
iTerm2KittyGraphics OK; pixel mouse permanently reset
Apple TerminalNoneHeadless only — interactive open refuses

Run terminal-fenster doctor inside your terminal to see which backend you get and why.

Headless mode

--headless skips TTY graphics. Use it in CI, scripts, SSH without a graphics terminal, or Apple Terminal. Control the browser via JSON: 

terminal-fenster action state
terminal-fenster action navigate --url https://example.com
terminal-fenster action quit

MCP automation

Sixteen browser tools over stdio — navigate, snapshot, click, type, screenshot, and more. The MCP server starts an isolated Chromium session; actions use the same engine input path as the interactive browser. 

terminal-fenster mcp-config   # JSON for your MCP client
terminal-fenster mcp          # run the server

See packages/mcp/README.md for the full tool list and security model.

Environment

  • TERMINAL_FENSTER_ENGINE — path to engine checkout
  • TERMINAL_FENSTER_MCP — path to packages/mcp/index.js
  • TERMINAL_FENSTER_FPS — paint rate ceiling (default follows display)
  • TERMINAL_FENSTER_SHM=0 — disable Kitty shared-memory fast path

Develop from source

cargo build -p terminal-fenster --release
(cd apps/engine && npm ci)
tools/release-check.sh          # full gate
cargo test --workspace --locked
