How it works

One process owns your TTY. Another runs sandboxed Chromium. They talk over a private Unix socket — JSON for control, binary for frames.

Real Chromium

Electron 43 / Chromium 150 offscreen rendering. Same engine as a desktop browser, not a DOM-to-text hack.

Kitty graphics

Frames go out as Kitty protocol images with damage encoding and optional shared-memory fast path on local terminals.

Your input, unchanged

Clicks, hover, scroll, and keyboard events map back to the page. The terminal is restored on every exit path.

Install

macOS or Linux. Rust 1.80+ and Node 22.12+ for a source build. Interactive browsing needs Ghostty, kitty, or WezTerm.

One-liner clones main and runs install.sh. Pin TERMINAL_FENSTER_REF to a release tag when we ship signed binaries.

curl -fsSL https://raw.githubusercontent.com/zent7x/terminal-fenster/main/install.sh | bash
# or clone manually
git clone https://github.com/zent7x/terminal-fenster.git
cd terminal-fenster && ./install.sh

# interactive (Ghostty / kitty / WezTerm)
terminal-fenster setup
terminal-fenster open example.com

# headless — any terminal, scripts, CI
terminal-fenster open example.com --headless
